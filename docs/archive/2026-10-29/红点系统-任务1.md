## 3. 先讲清三个工程概念

### 3.1 测试怎么跑：`tsc` 编译 → `node --test` require 编译产物

Node 不能直接跑 TS。项目现有做法（`tools/logtest`）是：

```bash
tsc -p tools/reddottest/tsconfig.json        # 编译到 .reddottest-out/
node --test tools/reddottest/reddot.test.mjs # 测试 require 编译后的 JS
```

`tsconfig` 的 `include` 是**显式文件清单**，不要改成 `Frame/RedDot/**/*.ts`：任务 3 会加 `RedDotBadge.ts`（import `cc`），glob 会把它编进来导致 `TS2307`。

### 3.2 为什么缓存 `total`，而不是每次 `Get` 递归求和

聚合值是红点最高频的读操作（每个 badge 都读），必须 O(1)。所以写操作负责维护缓存：写入后沿父链向上重算，读操作直接查表。代价是「凡是批量改动子树的操作（`clearTree` / `resetCounts`），必须自底向上把子树里每个节点的 `total` 都重算一遍」——设计稿 §5.1 的「子树重算」说的就是这件事，漏了就是 v2 的 B1 缺陷。

### 3.3 脏集 + 批量 + 事件三件套

- **脏集**：一次操作后，哪些 ID 的显示可能变了。规则固定为 `total 变化 ∪ 新注册 ∪ 被移除(含子孙)`。
- **批量**：`batch` 内只累积脏集，最外层结束才广播一次。必须 `try/finally`，否则一次异常会让深度卡住、之后再也不广播。
- **事件**：监听器收到的是新的一份 `Set` 快照；监听器里再写红点时，新脏 ID 进下一轮，不要同步递归。

### Step 0：环境确认

确认项目依赖已安装（仓库根目录有 `node_modules/` 且包含 `typescript`）。没有就先 `npm install`。本任务不需要 Cocos 编辑器。

### Step 1：`RedDotFormat.ts`

- `normalizeCount(v)`：非有限 → 0；负数 → 0；小数向下取整。
- `formatRedDotCount(count, maxCount)`：`maxCount` 非有限或 < 1 按 99；`count > maxCount` 返回 `${maxCount}+`；等于上限返回原数字；`0` 返回 `"0"`。

### Step 2：`RedDotStore.ts` 骨架（先让工程能编译）

- 类型：`RedDotChange`、`RedDotNodeInfo`、`RedDotListener`。
- 三张表：`nodes: Map<string, { id, parentId, own }>`、`children: Map<string, Set<string>>`、`total: Map<string, number>`。
- 把所有公开方法签名补齐（可以先返回 0 / false），保证 `npm run test:reddot` 能进入「用例失败」而不是「编译失败」。
- 私有工具：`isValidId`、`getNode`、`recomputeUp`、`collectSubtree`、`recomputeNode`。

### Step 3：注册 / 查询 / 单次写入

- `register`、`unregister`、`isRegistered`、`get`、`getOwn`、`has`。
- `set` / `add` / `clear`：写入前记录「当前节点 + 祖先」的旧 `total`，写入后沿父链重算并比较，变化的 ID 进脏集。
- 规则按设计稿 §3.1 / §5.1：父节点必须先存在、`parentId !== id`、同父重复注册 no-op + `Log.warn`、异父注册 `Log.error` 拒绝、未注册查询返回 0/false。
- 归一：所有写入口走 `normalizeCount`；`add` 的 delta 先归一、相加后再 clamp、取整。

### Step 4：`clearTree` / `resetCounts`（子树重算）

- `clearTree`：收集整棵子树 → 全部 `own = 0` → 后序遍历自底向上重算每个 `total` → 再重算祖先 → 所有变化的节点进脏集。
- `resetCounts`：等价于对所有根执行 `clearTree`，包在隐式 batch 里只广播一次；保留注册树。

### Step 5：事件 / batch / 重入

- `onChanged`：内部数组保存；广播时逐个 `try/catch`（单个监听抛异常只 `Log.error`，不影响其他）；返回的退订函数重复调用是 no-op。
- `batch`：深度计数 + `try/finally`；最外层结束 flush 一次；嵌套只发一次；`fn` 抛异常时先 flush 已累积脏集（或明确丢弃并 `Log.error`）再把异常向上抛。
- 重入：`_emitting` 标记；每轮最多广播一次；同一监听器连续 3 轮以上 `Log.error`。
- 广播载荷：每次 `new Set(dirty)`，不复用可变集合。

### Step 6：契约收尾

- `snapshot()`：`{ id, parentId, own, total }`；满足 `total === own + Σ children.total`。
- `dispose()`：清空三张表 + 监听数组；重复调用安全。
- 把设计稿 §5.1 的「未注册 / 非法输入契约表」逐行对齐（未注册查询返回 0/false、`set/add` 记 error、`clear/clearTree/unregister` 静默）。

## 7. 本任务常见坑

1. **`Math.max(0, Math.floor(NaN))`** 仍是 `NaN`；必须先 `Number.isFinite` 判断。
2. **`clearTree` 只重算祖先** → 子孙 `total` 残留，事件发了但视图读到旧值。
3. **`batch` 没有 `try/finally`** → 一次异常后深度永久 ≥ 1，之后所有事件静默。
4. **广播复用同一个 `Set`** → 监听器拿到的是下一轮内容。
5. **监听器里抛异常没隔离** → 后面的监听器全部不再执行。
6. **`resetCounts` 只清 `own`** → `total` 不更新、不发事件，导入存档后红点残留。
7. **`snapshot` 依赖 `Map`/`Set` 的隐式顺序** → 测试已做排序，实现按注册顺序返回即可。
8. **把 `99` 封顶写进 Store** → 存储必须是真实值，封顶只在 `formatRedDotCount`。
9. **日志 tag 乱写** → 统一 `'RedDot'`。
10. **改测试或改设计稿来迁就实现** → 不允许；实现与规格冲突时先找我确认。
