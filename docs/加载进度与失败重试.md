# 启动任务：加载进度与失败重试

日期：2026-10-29。状态：已实现并通过自动回归，实机验收待完成；当前结果见[当前实现](当前实现.md)。下文保留实施要求供核对，后续任务见[标题进入与恢复检查](标题进入与恢复检查.md)。保留现有 BGM；用户实现游戏脚本、场景和 Prefab，助手讲解、维护测试并审查。不保留 Python 界面生成脚本。

## 目标与范围

把当前启动流程改为：

`Boot 场景兜底提示 → 装配 UI → 打开加载页 → 恢复设置 → 初始化红点 → 准备标题 → 进入标题`

失败时停在可见界面，显示中文原因与“重试”；成功之前不允许点击标题进入主页。本次不做配置下载、编队、战斗恢复，也不改通用 UI 框架。

改动前 `AppEntry.start()` 在打开加载页前就初始化了设置/红点，`BootLoadingWin` 只显示一句提示。现已将“只执行一次的装配”与“可重试的启动步骤”分开。

## 文件与职责

| 文件/资源 | 改动 |
| --- | --- |
| `assets/Scripts/Model/App/AppEntry.ts` | 装配、执行步骤、持有启动状态、失败处理、重试和销毁保护 |
| `assets/Scripts/Model/App/UI/BootLoadingWin.ts` | 显示步骤、百分比、失败信息；上报重试点击 |
| `assets/resources/ui/app/BootLoadingWin.prefab` | 编辑器增加 ProgressBar、百分比 Label、重试 Button，绑定组件字段 |
| Boot 场景（挂 AppEntry 的场景） | 增加常驻的启动提示 Label 和重试 Button，供加载页自身失败时使用 |

不必先抽通用任务调度器；本次启动步骤很少，用 AppEntry 的私有方法即可。名称可按现有风格调整，职责不要混在一起。

## 实施顺序

### 1. 先做加载页的展示能力

保留 `_loadingText`，增加进度条、百分比和重试按钮。提供类似 `showProgress(completed, total, message)`、`showFailure(message)` 的公开方法；由 AppEntry 调用，不让加载页自己初始化设置或红点。

- 正常状态显示“正在恢复设置”等当前步骤和完成比例；重试按钮隐藏。
- 失败时保留最后成功的进度，显示“启动失败：……”和重试按钮。
- 重试开始立即隐藏/禁用按钮，清除旧错误。
- 按钮事件通过 `BindingScopeSignals.onClick(this.binder, ...)` 注册。回调用打开 payload 传入，不直接访问 AppEntry 单例。
- `onOpen` 只重置本次展示；全局初始化不能放进去。

先在编辑器给进度手动赋值，检查 0%、50%、100%、失败文案和按钮布局，再接真实流程。

### 2. 拆开 UI 装配和启动尝试

AppEntry 先检查 `_uiRoot`、`_soundManager`，配置 Sound，建立注册表并初始化一个 UIManager。`manager.open()` 返回的是 `UIVo | null`，通过返回对象的 `ui` 取得窗口，并核对它确实是 BootLoadingWin；不是直接将 open 的返回值当窗口。

UIManager 已初始化时重试应复用它。若装配中途失败，只清理本次创建但未成功装配的实例；不要留下第二个 ticker 或层级根。不要把整个 `start()` 当作按钮回调重复调用。

Boot 场景中的提示/按钮不依赖 resources 加载；加载页打开后隐藏场景兜底。加载页打开失败或缺少必需组件绑定时显示兜底，让玩家还能重试。若兜底节点本身也未绑定，记录明确的配置错误供开发者修复，不能承诺运行中自动修复场景绑定。

### 3. 接真实进度

加载页成功打开后，本次固定三个步骤：

| 步骤 | 工作 | 完成后的进度 |
| --- | --- | --- |
| 恢复本地设置 | `SettingsService.Initialize()`，在 BGM 播放前应用音量 | 1/3 |
| 初始化入口状态 | `RedDot.Initialize()`、注册入口树；DEV 演示种子只写一次 | 2/3 |
| 准备标题页 | 等待 `manager.open<TitlePayload>('TitleWin', ...)` 成功并检查返回值 | 3/3 |

开始时 0/3；只有步骤成功后才增加 completed。显示百分比是**完成步骤数比例**，不是资源字节下载比例。同步步骤很快，可以跳过中间画面；不加计时器或人为延迟来制造加载时间。

设置读取损坏时回退备份/默认值属于现有服务的正常降级，不因使用默认值就弹启动失败；保留服务原有的保护和日志。抛出的异常才进入本任务的失败分支。

`Sound.PlayBgm()` 返回 void，内部异步错误不通过这次启动等待传播。设置恢复后照常调用，避免每次重试重复播放；本任务不将 BGM 加载列为进度步骤，也不据此宣称音频资源全部准备完成。

注意：TitleWin 和加载页默认同为窗口，新窗口可能通过 hideBelow 隐藏旧窗口。启动期间把加载页放到现有 `EUILayer.Loading`，并设置适当的 `hideBelow` 阻止未完成标题的显示/交互；标题成功后设 100% 再关闭加载页。不强制让 100% 停留一段时间。

### 4. 失败与重试

AppEntry 至少区分 idle/running/failed/ready/disposed；一次只允许一个启动尝试。点击重试从三个步骤的起点重新执行，不继续半个失败步骤。

- 使用递增的尝试编号；每次 await 返回后同时核对编号、组件仍有效且未销毁，旧结果不改界面、不关闭新窗口、不继续进入标题。
- 点击处理同步设置 running 再开始 await，防止连点产生多个尝试；仅 failed 可以重试。
- 成功完成的全局初始化通过标记复用，不因后续标题失败重复初始化。尤其 SettingsService 不反复读取、DEV seed 不重复写入；只在整段初始化成功后设置对应标记。
- `manager.open()` 返回 null 也属于失败；不要只处理 Promise rejection。
- 日志记录原始 error 和失败步骤；界面显示清晰的中文阶段提示，不直接显示对象字符串或堆栈。
- 重试后清除错误、重置显示进度。复用的已完成步骤仍按真实复用结果计为完成。
- `onDestroy` 先使尝试编号失效，再按现有方式 dispose；之后返回的异步结果不能更新窗口或启动后续步骤。
- 标题进入主页仍使用现有防连点逻辑；主页打开失败由 TitleWin 原有捕获处理，不把它当成启动加载失败。

## 验收与交付

| 情况 | 期望 |
| --- | --- |
| 正常启动 | 进度来自三个步骤；标题成功后加载页关闭，只有一个标题实例 |
| 标题打开首次失败，第二次成功 | 显示失败和重试；重试进入标题，设置和 DEV seed 不重复初始化 |
| 打开返回 null / 抛异常 | 两种情况都进入可见的失败状态，无未处理 Promise rejection |
| 加载页资源缺失 | 场景兜底提示和重试可用，不尝试用另一个资源弹窗显示错误 |
| 快速连续点击重试 | 只执行一次尝试，不增加 UIManager、ticker 或红点订阅 |
| 等待期间销毁 AppEntry | 后到结果无界面更新、无进入标题、无访问已销毁节点 |
| 损坏设置或存储不可用 | 沿用设置服务回退/保护行为，能继续启动，不覆盖受保护旧数据 |
| 标题点击进入 | 仍可进入主页，编队/关卡/设置入口与红点行为无回归 |

故障通过 DEV 临时替身或断点注入，例如仅让第一次 TitleWin open 返回 null；不要提交错误资源路径，不要把测试开关放进正式设置。故障验证结束后移除临时代码。

实现后由助手补启动回归测试：覆盖失败后重试、防连点、已完成初始化复用和销毁后的异步隔离。界面实际进度与场景兜底仍需 Cocos 预览。
