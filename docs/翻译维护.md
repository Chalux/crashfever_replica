## XLSX 导入兼容修复

Localization Editor 1.0.4 的 XLSXReader 将文件 Buffer 的 `.buffer` 以 `type: 'string'` 传给 SheetJS；底层 ArrayBuffer 可能含有文件之外的字节，导致 `Unrecognized LOTUS BOF 91` 或错误识别为 Sheet1。当前修复覆盖全部五份打包入口：`electron-main/main.js`、`electron-main/scene.js`、`electron-renderer/default.js`、`electron-renderer/builder.js`、`electron-renderer/l10n-label-inspector.js`。统一用 `new Uint8Array(data)` 复制有效字节并以 `type: 'array'` 读取；先校验 ZIP 文件头，错误时显示实际导入路径。最初只修主进程/场景两处的版本已被替代。翻译表仍为标准 XLSX。

回归检查：`node --test tools/uitest/localization-import.test.mjs`，直接使用每份入口随附的 SheetJS 解析当前中文表，并验证带偏移的 Buffer（启用 Node process 环境）。插件更新/重建可能覆盖本地修复，更新后需复跑检查。修改后重新启动 Cocos Creator，使所有进程重新加载插件，再导入翻译表。离线回归不替代编辑器实际导入验收。

后续定位：编辑器日志确认导入路径正确，但其异步 fs-extra 读取结果未通过文件头校验；同路径文件的磁盘 ZIP 校验正常。当前五份 XLSXReader 改用原生 `fs.readFileSync`，不再经过该异步桥；完整 reader.read 实际文件测试加入回归。此改动尚待编辑器实际导入确认，不能仅凭离线通过认定问题已经解决。

再次复核：编辑器在 readFileSync 版本下仍报告 14833 字节、文件头 `0,0,91,0,229,139,135,101`；终端和独立主机读取入口均读到 10737 字节，ZIP 头 `80,75,3,4`。因此 readFileSync 版本也未解决实际编辑器问题。当前 reader 改为 openSync/fstatSync/readSync 循环读取有效字节并 finally closeSync，读取与解析之间不再 await。回归测试禁止调用 readFile/readFileSync，验证五份完整 reader 的文件描述符读取。尚未取得编辑器成功导入结果，根因仍不能定为某一具体封装。

## 导入丢键修复

已确认 `TranslateDataSourceService.updateTranslateData` 会把不在索引中的同文案新键合并到旧键。CSV/XLSXReader 创建的 External 条目现在按 key 保留，不按 value 去重；同文案的不同键均写入索引与语言数据。覆盖已有键只更新相应值，保留原关联和其他条目。`localization-preservation.test.mjs` 用真实生产合并方法验证相同文案双键、重复导入更新、节点关联和媒体项保留。

中文语言库、索引、CSV 与 XLSX 已同步为 48 个语义文本键，恢复加载步骤提示并补齐动态弹窗文案。旧 XLSX 的 WPS sharedlinks 关系指向不存在的部件，已保留备份并重建标准三列表；不将这个问题等同于编辑器读到错误文件头的已确认根因。

XLSX 导入开始时新版会记录 `[Localization ImportPatch-r5] XLSX descriptor reader`。若日志仍停在旧代码位置且没有此标记，不能认定新版读取逻辑已加载。必须以实际编辑器导入、保存、重新打开后的键值完整性确认最终结果，离线测试仅为回归证据。

无需重启的备用入口：在同一“导入翻译”对话框选择 `assets/Translation/zh-Hans-CN.csv`。它使用插件原生 CSVReader，保留 key/sourceValue/targetValue 表头和 LanguageTag 行，内容来自中文 XLSX，另补 loading.failed。CSV 为 UTF-8，不依赖 XLSXReader。不要再全量扫描动态 Label，以免生成随机键并覆盖尚未编译的内存/磁盘语言数据。
