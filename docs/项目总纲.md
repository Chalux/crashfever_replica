## 1. 文档定位与协作方式

本文件记录需求讨论中已经确认的项目范围，替换最初未经确认的 0.1 草稿。后续设计、任务拆分与验收以本文件为依据；本文件不将尚未核实的原作细节作为事实，也不预先确定技术架构。

项目目的是学习开发。用户负责游戏功能与界面实现；助手负责拆分任务、讲解 Cocos、设计建议和代码审查，并维护必要工具、测试代码/用例和验收文档。用户熟悉 TypeScript，有 LayaAir 开发经验，不熟悉 Cocos；指导重点是引擎差异、节点与组件、Prefab、资源管理和生命周期。

现有工程使用 Cocos Creator 3.8.8 / TypeScript，已有 UI 框架及 UI 冒烟驱动。是否新增架构、接口和模块，应在对应阶段单独设计，不能将旧草稿中的方案视为已确认约束。

界面维护约定（2026-10-29）：一次性 Python 界面生成脚本使用后删除，以编辑器维护的 Prefab 为准，不保留生成器作为界面来源。

## 2. 项目目标与还原依据

- 参考当前最新日服 CrashFever，以用户提供的资料进行重制。
- 优先级依次为：战斗规则正确、消除手感贴近、画面细节贴近。
- 珠子运动、碰撞、消除和补珠节奏等尽可能还原原作；具体规则依据资料和逆向结果核实。
- 画面尽量复刻；可使用原作音效；2026-10-29 用户调整：保留背景音乐及现有 BGM 设置。
- 全部文本使用简体中文，包括界面、角色与技能描述、敌人提示、关卡说明及图片内嵌日文。助手根据日文翻译，用户确认。
- 原作资料不足或相互矛盾时，助手列出问题，由用户裁定，不自行确定规则。
- 可先使用明确标记的占位资源和测试配置推进开发；不确定的战斗规则仍须确认。
- 角色、关卡逐批加入，首批名单不预先锁定，通过配置随时填充。开发验证可使用最小测试配置。

“当前最新日服”是参考方向，不表示已核实所提供包体的版本。每次分析应记录实际资料或包体版本；原作未来更新不自动成为已经确认的新增需求。

## 3. 平台与范围

支持 Windows、Android、浏览器。保持原作竖屏比例，宽屏留边。鼠标左键点击、按住对应触屏点击、长按。

游戏为离线单人，不做联网、账号、资源下载和多人协力。正常版本的战斗操作与辅助功能参照原作，具体功能待核实；额外保留本项目确认的回合恢复功能。

| 纳入范围 | 不纳入当前范围 |
| --- | --- |
| 启动加载、标题、主界面、设置 | 联网、账号与在线资源下载 |
| 角色详情、角色选择、30 套编队 | 角色养成、等级与觉醒流程、抽卡 |
| 原作关卡选择、出战准备、战斗及结算 | 体力、解锁、每日次数、奖励掉落 |
| 本地保存、跨平台存档导入导出、战斗恢复 | 通关标记与历史成绩保存 |
| 开发版本调试功能 | 当前实现解码、团战 BOSS 等特殊模式 |

特殊模式只保留扩展接口，后续可新增战斗逻辑；当前不实现相关模式内容。

## 4. 配置与扩展

原作内容和自定义内容统一使用配置描述。角色属性、技能组合、敌人行动、关卡规则等由配置提供；配置组合程序已有机制，全新机制需先补代码实现，再供配置使用。不开发通用逻辑脚本系统。

直接编辑配置文件，不开发可视化编辑器。新增内容以新增配置为主要方式；未要求游戏运行时导入外部内容包。

角色直接可用于编队，使用提供的属性，不指定等级或觉醒状态。完整保留主动技能、被动能力、C 珠效果等原作能力。具体配置结构和执行机制在技术设计阶段确定。

## 5. 页面与整体流程

启动流程：

`本地加载 → 标题页 → 点击屏幕进入 → 检查战斗恢复数据 → 主界面或恢复战斗`

- 加载页负责本地初始化、读取配置和存档，显示加载进度。
- 标题页沿用原作点击屏幕进入的方式。
- 发现恢复数据时，弹出“继续战斗 / 放弃战斗”；放弃会清除数据。
- 恢复数据与当前配置不兼容时，提示后返回关卡选择，不继续加载该场战斗。
- 主界面尽量还原原作布局，只保留本项目需要的编队、关卡选择、设置等入口。

出战流程：

`主界面 → 关卡选择 → 出战准备 → 战斗 → 结算或退出`

出战准备可切换编队、进入编队编辑；退出编辑后返回出战准备。默认选中上次选择的编队，该选择跨启动保存。

## 6. 编队与角色选择

- 固定提供 30 个编队位置，支持命名、同名和队内位置调整。
- 队伍固定 4 人（2026-10-21 确认）。助战位已包含在这 4 人内，本项目不单设助战位。
- 不保留原作编队限制；同一角色可重复上阵。
- 允许空槽位，但至少一名角色才能出战。
- 点击槽位打开角色选择列表，选中角色后立即替换并返回编队界面。
- 同一角色在列表中只显示一项，可反复选入不同槽位。
- 列表最前方固定增加“移除角色”，使用普通角色项的选择方式，不受筛选与排序影响。
- 拖拽交换队伍中的角色位置。
- 角色筛选与排序沿用原作，具体条件后续核实。
- 长按角色进入详情，查看属性、主动技能、被动能力、C 珠效果等。
- 当前不纳入“清空整队”和“复制编队”。

编队和队名编辑期间仅保存在内存；切换编队仍保留各队修改。退出编队界面或进入战斗时统一写入存档。程序意外关闭时，丢弃本次尚未保存的编队修改。

## 7. 关卡选择与出战准备

- 复刻原作关卡，内容逐批配置加入。
- 已配置关卡全部开放，按配置分类和顺序展示，不随现实日期轮换。
- 无体力、解锁条件、次数限制或奖励掉落。
- 支持按元素、难度筛选，不提供关卡名称搜索。
- 没有配置关卡时显示“暂无关卡”，仍可返回主界面使用编队和设置。
- 出战准备展示关卡说明、敌人及机制提示，具体展示内容参照原作。
- 不保存通关标记或历史成绩。

## 8. 战斗与详情

以覆盖原版战斗逻辑机制为目标，按每批角色和关卡的实际需求逐步实现，并保证后续可扩展。操作次数、连接判定、特殊珠、伤害公式、属性、效果叠加、敌方行动和结算时机等，均须根据实际资料核实，不能凭印象制定。

正常版本的战斗操作功能还原原作。自动战斗、倍速等是否存在及具体行为待核实，不因为讨论中举过例子就默认纳入。

战斗内长按角色显示战斗专用详情气泡框，查看期间暂停战斗计时与表现。气泡框字段、数值含义和交互以原版逆向结果为准，尚未确认显示基础属性、动态属性或哪些状态字段。

胜利结算不展示奖励，只保留战斗结果与“重新挑战 / 返回关卡选择”；胜利后清除战斗恢复数据。

失败后提供“返回当前回合起点 / 重新挑战 / 退出战斗”。退出返回关卡选择。

## 9. 暂停、回合回退与重试

### 9.1 暂停

战斗提供手动暂停按钮。Android 切到后台、Windows 或浏览器失去焦点时自动暂停并显示暂停界面；返回后由玩家点击继续。

暂停界面提供：继续、返回当前回合起点、重新挑战、退出战斗。后三项执行前弹出确认框。

普通暂停恢复从暂停瞬间继续，保留本回合已完成的操作，不自动回退回合。

### 9.2 回合起点恢复

在玩家回合开始时保存恢复快照。战斗中可不限次数返回当前回合起点，不能返回更早回合。程序中断后继续战斗也回到当前玩家回合起点。

恢复盘面、双方 HP、技能冷却、状态效果、敌人行动计数等完整战斗状态，但不恢复随机状态。已有盘面按快照恢复；恢复之后发生的随机行为重新抽取，因此同样操作不保证同样结果。

玩家回合起点的精确事件顺序，例如回合开始自动效果结算前后，尚待原作机制分析后确认。

### 9.3 重试与退出

重新挑战从头开始整场战斗，重置战斗状态并重新随机生成开局，不等同于当前回合回退。

主动退出战斗会清除恢复数据，返回关卡选择。主动退出与程序意外关闭区别处理；程序中断保留最近的有效回合起点。

## 10. 本地存档与迁移

本地保存内容包括：

- 全部编队、编队名称。
- 设置。
- 上次选择的编队。
- 尚未结束战斗的恢复数据。

不保存通关标记和历史成绩。

Windows、Android、浏览器的存档可手动导出、导入并互相迁移。导出包括上述全部内容。仅在非战斗状态允许导入；导入前确认，导入后整体覆盖已有数据，不合并。

导入编队引用了尚未加入的角色时，对应槽位直接置空。战斗恢复配置不兼容时提示后返回关卡选择。

存档格式、版本兼容判定、写入时机及异常恢复方案在技术设计阶段确定。

## 11. 设置与开发调试

正常设置包含音效音量、BGM 设置、原作支持的战斗显示选项、存档导入导出。原作显示选项的具体清单待核实。

仅开发版本提供以下调试能力：

1. 修改双方 HP、技能冷却和状态效果。
2. 查看伤害计算及效果触发顺序。
3. 查看配置与运行错误。

不加入指定/修改盘面、跳过动画或逐步执行结算等调试功能。正常版本不开放调试入口和能力。

## 12. 开发顺序与阶段验收

按用户指定顺序推进，不采用旧草稿的珠盘优先计划。

| 阶段 | 工作范围 | 阶段验收方向 |
| --- | --- | --- |
| 第一阶段：启动界面 | 本地加载、标题、主界面及所需基础设置/存档入口 | 可启动、点击标题进入，入口与恢复提示流程正确；战斗未实现时先验证流程占位 |
| 第二阶段：角色编队 | 角色配置、选择、详情、30 套编队、拖拽、保存 | 可重复编入角色、移除、改名、切队、退出保存；空队不可出战 |
| 第三阶段：战斗与关卡选择 | 原作关卡、筛选、准备、战斗、结算、暂停、恢复与调试 | 完成选择→准备→战斗→结算闭环，并验证暂停、回退、中断恢复和退出 |

阶段内任务由助手拆分，用户实现。先讲清目标、Cocos 对应概念和验收方式，再由用户编码；不预先替用户铺设实现代码。

验收还应覆盖三平台操作、竖屏显示与存档迁移。具体测试用例、性能目标和设备清单随阶段细化，不在需求阶段自行设定数值。
